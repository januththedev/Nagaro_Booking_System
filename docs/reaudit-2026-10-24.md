## Release verdict

**Changes are implemented and locally tested. Production admin is not certified repaired.** The live authenticated `/admin` and `/admin/login` returned `INTERNAL_ERROR` during this re-audit. Production logs/database could not be inspected: the Vercel connection returned 403 for the owning team. No production migration, customer booking, account change, payment, merge, or deployment was performed.

An outdated staff-account schema reproduces the post-login crash in actual PostgreSQL: authentication can succeed with `SELECT *`, while session resolution explicitly selects newer columns. Dropping `admin_user.must_change_password` reproduces this boundary. This is a **supported hypothesis**, not a confirmed production diagnosis. Network or other production failures remain possible.
